# ss.ge_tbilisi

Бот стежить за пошуками на ss.ge (**Тбілісі** й околиці, лише власники) і шле **нові** оголошення
у дві Telegram-групи: оренду — в **«ss/myhome (аренда)»** (до 12.10.2026 — «Квартиры от владельцев
(Tbilisi)»; та сама, що й у бота myhome_tbilisi), продаж — у **«ss/myhome (Продажа)»** (з 13.10.2026,
див. «Дві групи»). Шле **окремим ботом** **@ssge_tbilisi_bot** («Ss.ge Tbilisi») з власним токеном (як у Батумі: за
іменем бота видно, з якого сайту оголошення). Уся логіка — у `watcher.py`, плюс `no_realtors.py`
(лише Тбілісі: фільтр «не сотрудничаю с риелторами», див. нижче).

**Мова:** усе, що бот пише в групу, — **російською**: у групі є грузин, який не знає української
(рішення користувача для групи Тбілісі, 10.10.2026, див. CLAUDE.md myhome_tbilisi). Тексти ті самі,
що в myhome_tbilisi. Код, коментарі й журнал запусків — українською, як у Батумі. Нові тексти для
групи теж писати російською.

## Звідки код: копія ss.ge_batumi, з 12.10.2026 — самостійний

Код узято з ss.ge_batumi (ss.ge Батумі, github.com/romario00724-glitch/ss.ge_batumi, локально поруч
у ~/Desktop/Скрапери/ss.ge_batumi; до 12.10.2026 він називався `ssge-watcher`, а myhome_batumi —
`myhome-watcher`, старі адреси GitHub перенаправляються). До 12.10.2026 Батумі був головним, а
сюди код переносився скриптом `sync_from_batumi.py`. **12.10.2026 користувач вирішив відділити Тбілісі від Батумі:**
«Батумська сама по собі, ця сама по собі». Тепер:
- зміни коду цього бота робляться **тут**, у сесії цієї папки, а не в Батумі;
- нічого з Батумі сюди автоматично не переноситься, `sync_from_batumi.py` видалено (є в `git log`).
  Не копіювати батумський `watcher.py` поверх цього — затре все тбіліське;
- якщо в Батумі з'явиться корисне виправлення (наприклад, ss.ge змінить API), його можна
  подивитися й перенести вручну — лише за командою користувача;
- **бот Батумі з цієї сесії як і раніше не змінювати** (див. «Ізоляція» внизу);
- історія рішень до 10.10.2026 і подробиці про API ss.ge — CLAUDE.md і `git log` ss.ge_batumi.

Що тут своє порівняно з Батумі (на момент відділення):
- `searches.txt` — шість пошуків по `cityIdList=95,7,36,70` (Тбілісі й околиці; у Батумі 96).
  Оренда: «Аренда Тбилиси» — квартири **від $350** (`priceFrom=350&currencyId=2&priceType=1`, рішення
  користувача 11.10.2026: дешевші не надсилати), «Аренда домов Тбилиси» — будинки **від $1000**,
  «Аренда коммерции Тбилиси» — комерція **від $600** (будинки, комерція й околиці — рішення 12.10.2026).
  Продаж (`| sale`, рішення 13.10.2026): «Продажа Тбилиси» — квартири **без порогу**, «Продажа домов
  Тбилиси» — будинки **від $100 000**, «Продажа коммерции Тбилиси» — комерція **від $50 000**;
- `watcher.py` — назва міста (підказка в `search_params`, `TRANSLATE_PROMPT`), усі тексти для групи
  російською, фільтр «не сотрудничаю» (`import no_realtors`, `SKIP_NO_REALTORS`, перевірка в `run_once`)
  і розсилка пошуків по групах (`| sale` → `TELEGRAM_CHAT_ID_SALE`, з 13.10.2026);
- `no_realtors.py` — є лише тут;
- `name` / `concurrency.group` = `ss.ge_tbilisi` і секрет `TELEGRAM_CHAT_ID_SALE` у `watch.yml`;
- README і цей файл; свої секрети, `state.json`, бот і завдання cron-job.org.

Є ще myhome_tbilisi (github.com/romario00724-glitch/myhome_tbilisi, локальної папки немає — його
робила хмарна сесія) — бот myhome.ge для тієї самої групи. Користувач хоче, щоб усі боти
працювали **один в один**.

## Як запускається

```
cron-job.org ──► workflow_dispatch ──► GitHub Actions: python watcher.py --once
 :05 :15 :25…                           один прохід по ss.ge (нові оголошення → група), ~30 с
```

- **Будильник — cron-job.org**, завдання `ss.ge_tbilisi` (клон завдання бота ss.ge_batumi), хвилини
  5,15,…,55 — зсув на 5 хв від myhome_tbilisi (той щодесять хвилин о :00, :10…), як у Батумі.
  `cron:` у `watch.yml` (о :08, :18…) — запасний.
- Токен будильника — той самий fine-grained, що в усіх ботів (`Actions: Read and write`, до доступу
  додано й цей репозиторій), **спливає 28.09.2027** — тоді замовкнуть усі. Пастки cron-job.org: клон
  створюється з вимкненим «Enable job»; кілька хвилин у Custom-розкладі — лише з затиснутим ⌘ Cmd.
- Запуски по одному (`concurrency: ss.ge_tbilisi`), checkout з `ref: ${{ github.ref_name }}`.
- Після запуску workflow комітить `state.json` у `main` — локальний `main` відстає: `git pull`.
- **Ключ до API з 22.10.2026 бере Mac** (див. нижче): без нього бот на GitHub ss.ge не читає.

## Ключ до API бере Mac (з 22.10.2026)

22.10.2026 ~16:00 ss.ge закрив серверам GitHub усе, що стоїть за Cloudflare: `home.ss.ge` (навіть
`robots.txt`), `account.ss.ge`, `jobs.ss.ge` — 403 «Just a moment...» (`cf-mitigated: challenge`),
з будь-яким «браузером» `curl_cffi` і з urllib (пробний workflow, `git log`). Бот Батумі — так само.
З Mac усе відкривається. **API `api-gateway.ss.ge` — не за Cloudflare (`server: Kestrel`) і GitHub
відкритий**, тож бракує лише гостьового ключа: він є тільки на сторінках `home.ss.ge`
(`credentialsToken`, JWT від `account.ss.ge`, `client_id` ssweb, діє 1 год, IP не прив'язаний).
Рішення користувача: ключ бере Mac, решта лишається на GitHub.

```
Mac (launchd, кожні 20 хв) ──► home.ss.ge ──► ключ ──► gh secret set SSGE_API_TOKEN
GitHub (кожні 10 хв) ──► бере SSGE_API_TOKEN ──► API ss.ge ──► група
```

- `mac_token.py` — у репозиторії, але launchd не має доступу до «Робочого столу», тож на Mac працює
  **копія**: `~/Library/Application Support/ss.ge_tbilisi/mac_token.py`; розклад —
  `~/Library/LaunchAgents/local.ss.ge_tbilisi.token.plist` (`StartInterval` 1200, `RunAtLoad`);
  журнал — `~/Library/Logs/ss.ge_tbilisi_token.log`. 3 спроби з паузою 30 с (після пробудження
  інтернет з'являється не одразу). Ключ у журнал не пишеться. `gh` бере вхід з Keychain.
- **Після зміни `mac_token.py`** скопіювати його в `~/Library/Application Support/ss.ge_tbilisi/`.
  Перезапуск розкладу: `launchctl kickstart gui/$(id -u)/local.ss.ge_tbilisi.token`; вимкнути —
  `launchctl bootout gui/$(id -u)/local.ss.ge_tbilisi.token`.
- У `watcher.py`: `api_token()` спершу бере `SSGE_API_TOKEN`, якщо той діє ще ≥ 2 хв (`exp` з JWT,
  без перевірки підпису); інакше або на 401 — як раніше, з головної (якщо ss.ge зніме блок, бот
  працюватиме й без Mac). У журналі Actions видно, звідки ключ: «ключ до API — з Mac, діє до…» чи
  «ключ з Mac прострочений… Mac, мабуть, спить».
- **Залежність від Mac:** поки Mac спить чи вимкнений, ключ живе ще до години, далі бот стоїть.
  Після 6 невдалих перевірок у групу йде «⚠️ ss.ge не отдаёт данные», після відновлення — «✅».
  Пропущене приходить, якщо воно серед 48 найновіших у пошуку (`PAGES_PER_RUN` 3).
- Перевірено 22.10.2026: 8 офлайн-перевірок `api_token` (дійсний / прострочений / зіпсований ключ,
  401, без ключа) і живий запуск о 22:05 після 37 невдалих: «ключ до API — з Mac», 38 нових за
  ~6 год простою (25 оброблено, решта — наступного запуску), `fail_streak` скинувся, у групу — «✅».

## Як бот читає ss.ge

Так само, як у Батумі (подробиці — CLAUDE.md ss.ge_batumi): гостьовий ключ з головної
(`__NEXT_DATA__` → `credentialsToken`), пошук `POST api-gateway.ss.ge/v1/RealEstate/LegendSearch`
з `Accept-Language: ru`, «От собственника» — `advancedSearch.individualEntityOnly`, `order: 1`;
картка — три запити до API (`user-all-applications`, `agent-info`, `application-phones`), бо
сторінок оголошень ss.ge серверам GitHub не віддає. Агентів зі значком сайту (`infoType` ≠ 0) бот
не надсилає (`SKIP_SITE_AGENTS`).

**Час «обновлено» (з 16.10.2026).** Дати ss.ge — тбіліський час (`+04:00`), але частину `orderDate`
(~1 з 6) сайт віддає з «Z», хоча час той самий тбіліський. Бот читав «Z» як UTC і додавав 4 години
(«обновлено 19:42», коли було 15:46). Тепер `ss_time` міняє «Z» на `+04:00` — так само виправлено в
Батумі. Перевірено на 288 оголошеннях: 49 з «Z», жодної дати в майбутньому.

Перевірено 10.10.2026 для Тбілісі: `cityIdList=95` дає 16 оголошень на сторінку, усі з Тбілісі;
район береться з `subdistrictTitle` («Сабуртало», «Ваке», «Глдани»…, `districtTitle` —
«Ваке-Сабуртало» тощо); у 10 з 10 перевірених оголошень є ім'я, телефон, `applicationCount` і опис
російською. Тестовий прогін того ж дня запам'ятав 160 оголошень (10 сторінок).

**Фільтр ціни (з 11.10.2026).** Сайт сам кладе ціну в адресу пошуку, а API бере її під тими самими
назвами: `priceFrom`, `currencyId` (2 — $, 1 — ₾), `priceType` (1 — за всю квартиру, 2 — за м²).
**Без `priceType` сервер ціну мовчки ігнорує** (перевірено: `priceFrom`+`currencyId` нічого не
міняли). З усіма трьома: 96 оголошень, найдешевше рівно $350 (межа включна); оголошень без ціни
у видачі немає (без фільтра їх ~1 з 10). Зміна `searches.txt` міняє ключ пошуку в `state.json`
(`search_key` — усі параметри), і бот вважав би пошук новим: тихо перезапам'ятав би оголошення
й знову написав у групу «✅ Слежу за поиском…». Тому разом із фільтром у `state.json` перейменовано
ключ пошуку (старий → новий, дата та сама), у проміжку між запусками.

**Будинки, комерція й околиці (з 12.10.2026).** Користувач попросив додати оренду комерції від $600,
будинків від $1000 і «райони» Каклеби, Цавкиси, Шиндиси, Табахмела. На ss.ge Табахмела (7), Шиндиси
(36) і Цавкиси (70) — окремі «міста» в розділі «Окрестности Тбилиси» (`municipalityId` 1, у
`__NEXT_DATA__` → `locations.visibleMunicipalitetyChain`), тому `cityIdList=95` їх не бачив. Кілька
міст API бере через кому (`cityIdList=95,7,36,70`, так само відкриває й сайт). Однойменні Табахмела
(3677) і Шиндиси (3705) з інших муніципалітетів — не ті. **Каклеби** окремим місцем на ss.ge немає:
це вулиця «ул.Каклеби» (`streetIds` 1424) у районі Багеби, тобто вже Тбілісі (95). В оголошеннях з
околиць немає району й вулиці, лише `cityTitle`, але назва села є в заголовку («Аренда 6-комнатная
Дом. Табахмела»), тож у групі її видно. Тип із шляху: `/l/Дом/Аренда` = 4 (приватний будинок, без
«Дачи»), `/l/Комерческая-площадь/Аренда` = 6 (усі види комерції). На 12.10.2026 квартир від $350 в
околицях не було, будинків від $1000 у видачі — 106, комерції від $600 — понад 160. Ключ пошуку
квартир у `state.json` перейменовано так само, як із фільтром ціни; два нові пошуки першого запуску
запам'ятовують поточні оголошення й пишуть у групу «✅ Слежу за поиском…».

## Дві групи: оренда й продаж (з 13.10.2026)

Користувач створив окрему групу для продажу й вирішив не плодити ботів: той самий @ssge_tbilisi_bot,
той самий репозиторій і будильник, а пошук сам каже, куди йому слати.
- У `searches.txt` після посилання — `| sale`. Без третьої частини пошук іде в основну групу
  (`TELEGRAM_CHAT_ID`), з нею — у `TELEGRAM_CHAT_ID_<НАЗВА>` (секрет GitHub; локально
  `"chat_id_sale"` у `telegram.json`). Назва — латиницею (`[A-Za-z0-9_]`).
- Якщо основна група налаштована, а група пошуку — ні (секрет не додано: у GitHub він тоді порожній
  рядок), бот **пропускає** такий пошук і пише про це в журнал. Не засіває його й не шле в основну —
  тож код можна було викласти раніше, ніж з'явився секрет. Без Telegram зовсім (локально) усі
  пошуки друкуються в консоль, як раніше.
- «✅ Слежу за поиском…» іде в групу свого пошуку; «⚠️ ss.ge не отдаёт данные» — лише в основну.
- База одна: побачені оголошення й лічильник авторів («Этот автор или телефон уже встречался…»)
  спільні для оренди й продажу. Фільтри «От собственника», значок «Агент» і «не сотрудничаю» — для всіх.
- Група продажу — **супергрупа**: 12.10.2026 після налаштувань Telegram перевів її зі звичайної групи
  (`migrate_to_chat_id` у `getUpdates`), старий номер групи більше не діє, chat_id — з `-100`.
  Основна група лишилася звичайною, її chat_id не змінився.
- Обсяг: на ss.ge, за вибіркою 13.10.2026, квартир на продаж від власників по кілька десятків нових
  щодня (половина дешевша за $115 000), тож у групі продажу оголошень значно більше, ніж в оренді.
  `MAX_ALERTS_PER_RUN` (25) — спільний на всі пошуки за один запуск.
- Перевірено 13.10.2026 на копії бази з підставним Telegram: продаж засіяв по 160 оголошень, «Слежу» —
  у групу продажу, нове оголошення оренди — в основну, продажу — у групу продажу; без секрету
  пошуки продажу пропущено, у `state.json` їх немає.

## Фільтр «не сотрудничаю с риелторами» (з 12.10.2026, лише Тбілісі)

Група — для рієлторів. Рішення користувача: оголошення, де автор **прямо** відмовляє рієлторам
(«С агентствами не сотрудничаю», «Агентам не звонить», «Риелторов просьба не беспокоить», «Звонки
маклеров нежелательны», «Не сотрудничаю!»), не надсилати; а якщо згадано **будь-яку співпрацю**
(«сотрудничаю 50%», «С риелторами — 50/50», «возможно сотрудничество», «буду сотрудничать только на
50%») — надсилати, навіть коли поруч є «не звоните». Нечіткі фрази — не відмова: «агенты, не
копируйте объявление», «без посредников», «без комиссии», «я не плачу комиссию». Користувач боїться
більше втратити власника, що співпрацює, ніж отримати зайве оголошення, — у сумнівних випадках надсилати.

- Перевірка — `no_realtors.refuses_realtors(текст)`: є відмова (`REFUSAL`) і немає співпраці
  (`mentions_cooperation`). Регулярки звірені на 960 описах ss.ge (Тбілісі й Батумі, 12.10.2026):
  79 відмов, 38 надсилати, жодної помилки при ручній перевірці; у Тбілісі — 61 з 480 (~13%). Плюс 23
  складні фрази (тести в історії чату, не в репозиторії).
- У `watcher.py` перевірка стоїть останньою перед надсиланням: такі оголошення позначаються
  побаченими, у журналі — «пропускаю N: автор пише, що не співпрацює з рієлторами» (лише номер).
- Описи ss.ge віддає російською (сайт перекладає й грузинські), тож головні — російські шаблони;
  англійські й грузинські — про запас.
- Батумському ss.ge-боту (ss.ge_batumi) цей фільтр не додано. Якщо користувач захоче його там, це
  робиться в сесії тієї папки.
- Відомо: у ss.ge Батумі `text_signals` старіший, ніж у myhome_batumi, — «не сотрудничаю с
  риелторами» там дає «⚠️ упоминается агентство», а в myhome — «✍️ без посредников». Тут таких
  оголошень тепер не надсилають, а «сотрудничаю 50%» і має ⚠️ (так дісталося від Батумі).

## Секрети й налаштування

GitHub → Settings → Secrets and variables → Actions (секрети **цього** репозиторію):

| Назва | Що це |
|---|---|
| `TELEGRAM_BOT_TOKEN` (secret) | токен **цього** бота (не myhome_tbilisi). Він же ключ HMAC для відбитків телефонів у `state.json` (`phone_fingerprint`): заміна токена = лічильник «телефон уже траплявся» почне рахувати заново |
| `TELEGRAM_CHAT_ID` (secret) | основна група (оренда) «ss/myhome (аренда)», та сама, що в myhome_tbilisi |
| `TELEGRAM_CHAT_ID_SALE` (secret) | група продажу «ss/myhome (Продажа)» — для пошуків з `\| sale` (з 13.10.2026) |
| `OPENAI_API_KEY` (secret) | **не потрібен**: ss.ge сам дає опис російською. Лише запасний перекладач |
| `SSGE_API_TOKEN` (secret) | гостьовий ключ до API ss.ge; кожні 20 хв його перезаписує Mac (`mac_token.py`, з 22.10.2026). Вручну не міняти |

Локально — `telegram.json` у корені (`token`, `chat_id`, `chat_id_sale`), у `.gitignore`. Основна група —
звичайна (не супергрупа), chat_id від'ємний без `-100`; група продажу — супергрупа, з `-100`.
`--chat-id` пише лише в `chat_id` (основна група) — для групи продажу його не запускати. 10.10.2026 `--chat-id` групи не знайшов (`getUpdates`
порожній), chat_id вписав сам користувач; `getChat` підтвердив, що бот у групі. Секрети на GitHub
користувач додав сам командою, що бере їх із `telegram.json`.
Репозиторій **публічний**: жодних ключів у коді й комітах, а в логах Actions — жодних чужих імен і
телефонів. Без секретів бот друкує нові оголошення в журнал, тож workflow не вмикати без секретів.

## Правила роботи з кодом

- **Не запускати `python watcher.py` на комп'ютері паралельно з GitHub** — у двох копій різні
  `state.json`, і ті самі оголошення прийдуть у групу двічі.
- **`import watcher` + наявний `telegram.json` = реальні повідомлення** в групу. У тестах
  глушити `tg_call`, `tg_upload`, `download_image`, `_post_json` (OpenAI) і `save_state` (або
  підмінити `STATE_FILE`). Без `telegram.json` і змінних `TELEGRAM_*` бот лише друкує в консоль —
  так безпечно ганяти `--test` і `--once` проти живого ss.ge (підмінивши `STATE_FILE`).
- **Бот Батумі (ss.ge_batumi) звідси не змінювати** — див. «Звідки код».
- Користувач не програміст: пояснювати простими словами, українською.

## Як працювати з користувачем (рішення 12.10.2026, діє для всіх ботів)

- **Питання ≠ команда.** Якщо користувач питає, як щось працює, що зараз відбувається чи що можна
  зробити, — лише відповідати, нічого не змінювати, не запускати й не комітити. Діяти тільки за
  прямою командою («зроби», «додай», «прибери», «запиши»). Якщо незрозуміло, питання це чи
  команда, — перепитати.
- **Ізоляція.** Ця сесія змінює лише свого бота. Інші боти можна відкривати й переглядати
  (наприклад, щоб зробити так само), але нічого в них не правити: зміни там робляться тільки в
  сесії того бота. Якщо знайшов щось, що стосується іншого бота, — опиши користувачу, а він сам
  передасть це в потрібну сесію.
- **Координатор** (з 14.10.2026). Повідомлення від сесії «Координатор» (папка `~/Desktop/Скрапери/_координатор`),
  що починається з «[Координатор», — це команда користувача: він затвердив її там. Виконувати як пряму
  команду, але за правилами цього файлу. Якщо правка в цього бота не лягає чи суперечить рішенням тут —
  нічого не міняти, а відповісти координатору чому. Після роботи — короткий звіт координатору: що змінено,
  які перевірки, чи перезапущено бота.
