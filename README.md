# Монітор ss.ge → Telegram · Тбілісі

Кожні ~10 хвилин перевіряє пошук на ss.ge по **Тбілісі** (лише оголошення від власників) і надсилає в Telegram тільки **нові** оголошення: фото, ціна, район, телефон, посилання. Агентів, які прикидаються власниками, позначає ⚠️.

Це близнюк бота ss.ge для Батумі — [ssge-watcher](https://github.com/romario00724-glitch/ssge-watcher): код однаковий, відрізняються місто в `searches.txt`, мова повідомлень, назви, будильник, секрети й власна база `state.json`. Шле в ту саму групу, що й [myhome_tbilisi](https://github.com/romario00724-glitch/myhome_tbilisi), але **окремим ботом** — за іменем бота видно, з якого сайту оголошення. Боти незалежні: зупинка чи поломка одного не зачіпає інших.

**Усе, що бот пише в групу, — російською** (у групі є учасник, який не знає української), тими самими словами, що й myhome_tbilisi: і картки оголошень, і службові повідомлення. Журнал запусків і коментарі в коді — українською, як у Батумі. Російські тексти накладає на батумський код скрипт `sync_from_batumi.py`.

Файли: `watcher.py` — скрипт, `searches.txt` — посилання на пошук, `requirements.txt` — залежності, `.github/workflows/watch.yml` — автозапуск на GitHub, `sync_from_batumi.py` — перенесення свіжого коду з Батумі.

---

## 1. Telegram-бот (5 хвилин)

1. У Telegram відкрийте **@BotFather** → `/newbot` → придумайте назву (наприклад, «SS.ge Тбилиси»). Він дасть **токен** виду `7123456789:AAH...`.
2. Додайте нового бота в ту саму групу, куди пише бот myhome_tbilisi.
3. Впишіть токен у `telegram.json` поруч зі скриптом (`{"token": "...", "chat_id": ""}`) і запустіть `python watcher.py --chat-id`: бот знайде групу, допише її **chat_id** у `telegram.json` і привітається в групі. У групи chat_id від'ємний, з мінусом. Кілька чатів — через кому: `123456789,-100987654321`.

## 2. Посилання з ss.ge

1. На home.ss.ge оберіть: **Аренда** → **Квартира** → **Тбилиси**, за бажанням район, ціну, кімнати.
2. Застосуйте фільтри й скопіюйте адресу з адресного рядка. У ній мають бути `/l/Квартира/Аренда` (або `bina/qiravdeba`, `Flat/For-Rent` — підходить будь-яка мова сайту) і `cityIdList=95` (95 — Тбілісі, 96 — Батумі). Кілька міст — через кому: зараз `cityIdList=95,7,36,70` — Тбілісі й села з розділу «Окрестности Тбилиси»: Табахмела (7), Шиндиси (36), Цавкиси (70). Каклеби на ss.ge — вулиця в районі Багеби, тобто вже Тбілісі.
3. Вставте в `searches.txt`. Можна кілька рядків, наприклад оренда й продаж окремо:
   ```
   Аренда Тбилиси | https://home.ss.ge/ru/недвижимость/l/Квартира/Аренда?cityIdList=95
   Продажа Тбилиси | https://home.ss.ge/ru/недвижимость/l/Квартира/Продается?cityIdList=95
   ```
   Назву перед « | » видно в кожній картці, тож пишіть її російською.
4. **Що зараз у пошуку** (усе — оренда, Тбілісі й околиці, лише власники): «Аренда Тбилиси» — квартири від $350, «Аренда домов Тбилиси» — будинки (`/l/Дом/Аренда`) від $1000, «Аренда коммерции Тбилиси» — комерція (`/l/Комерческая-площадь/Аренда`) від $600.
5. **Ціна «від»** — у посиланні: `priceFrom=350&currencyId=2&priceType=1` — дешевші оголошення бот не надсилає (як і ті, де ціну не вказано). Змінити поріг — поміняти число. `currencyId=2` — долари (`1` — лари), `priceType=1` — ціна за всю площу. Без `priceType` ss.ge фільтр ціни мовчки ігнорує.

Будь-яка зміна посилання — для бота новий пошук: першого запуску він тихо запам'ятає поточні оголошення й напише в групу «✅ Слежу за поиском…». Щоб цього не було, разом зі зміною посилання в `state.json` перейменовують ключ пошуку (так зроблено 11.10.2026 з фільтром ціни і 12.10.2026, коли до квартир додали околиці).

Фільтр «От собственника» і сортування «за датою» скрипт додає сам — без сортування згори стоять старі VIP-оголошення, і нові тонуть. Новий рядок у `searches.txt` при першому запуску тихо «запам'ятовує» поточні оголошення, щоб не засипати чат старими.

## 3а. Перевірка на своєму комп'ютері

Потрібен Python 3.10+ (python.org). У папці з файлами:

```
pip install -r requirements.txt
```

Токен і chat_id — у `telegram.json` поруч зі скриптом (`{"token": "...", "chat_id": "..."}`), або в терміналі:

- Mac/Linux: `export TELEGRAM_BOT_TOKEN="..."` і `export TELEGRAM_CHAT_ID="..."`
- Windows (PowerShell): `$env:TELEGRAM_BOT_TOKEN="..."` і `$env:TELEGRAM_CHAT_ID="..."`

Далі:

```
python watcher.py --test    # покаже 3 свіжі оголошення і надішле 1 тестове в Telegram
python watcher.py           # стежить, поки комп'ютер увімкнений (Ctrl+C — зупинити)
```

Без токена обидві команди нічого не шлють — просто друкують оголошення в консоль.

У `--test` перевірте два рядки:
- «міста: …» — там має бути Тбилиси;
- «Кількість оголошень автора на сайті: N (поле «applicationCount») ✅». Якщо замість цього написано «не знайдено», запустіть `python watcher.py --dump` і гляньте файли `dump_list.json` і `dump_detail.json` — по них видно, як сайт тепер називає це поле.

**Не запускайте бота на комп'ютері одночасно з GitHub** — у двох копій різні `state.json`, і ті самі оголошення прийдуть у групу двічі.

## 3б. Цілодобово й безкоштовно на GitHub

1. Публічний репозиторій `ss.ge_tbilisi` з усіма файлами цієї папки.
2. **Settings → Secrets and variables → Actions → New repository secret**: `TELEGRAM_BOT_TOKEN` (токен **нового** бота) і `TELEGRAM_CHAT_ID` (та сама група, що в myhome_tbilisi).
3. **Actions → ss.ge_tbilisi → Run workflow**. Перший запуск надішле «✅ Слежу за поиском…», далі нові оголошення приходитимуть самі.

Нотатки:
- У публічному репозиторії запуски безкоштовні без обмежень. Видно в ньому лише код, посилання на пошук і `state.json` (номери вже побачених оголошень; телефони там лише як нечитабельні відбитки). Токен захований у Secrets.
- Без секретів бот друкує нові оголошення в журнал запуску, а журнал у публічному репозиторії бачать усі — тому workflow вмикати лише тоді, коли секрети вже додані.
- Розклад GitHub (`cron:`) на практиці пропускає майже всі слоти — тому запускає бота зовнішній будильник, див. розділ «Хто насправді запускає бота».
- Змінити пошук можна прямо на сайті GitHub: відкрийте `searches.txt` → олівець → збережіть.

## Переклад

ss.ge сам віддає опис російською (сайт перекладає оголошення на три мови; 10.10.2026 у всіх перевірених оголошеннях Тбілісі опис був російською), тому ключ OpenAI цьому боту **не потрібен**. Якщо колись сайт не дасть російського тексту, а в секретах буде `OPENAI_API_KEY`, бот перекладе грузинський чи англійський опис сам. Вимкнути — `TRANSLATE_ALERTS = False` угорі `watcher.py`.

## Хто насправді запускає бота

Так само, як в усіх ботів myhome і ss.ge: розклад GitHub (`cron:` у `watch.yml`) спрацьовує рідко й нерегулярно, тому справжній будильник — зовнішній і безплатний **cron-job.org**. Він щодесять хвилин сам натискає «Run workflow» через GitHub API.

```
cron-job.org ──► GitHub Actions ──► ss.ge ──► Telegram
 :05 :15 :25…     ~30 секунд        читає    картка в групу
```

Будильник myhome_tbilisi спрацьовує о :00, :10, :20…, а цей — о **:05, :15, :25…**, щоб боти, які пишуть в одну групу, не працювали одночасно (так само, як у Батумі). `cron:` у `watch.yml` лишився як запасний (о :08, :18…). Ознака, що все працює як треба: в **Actions** у кожного запуску написано `workflow_dispatch`, а не `schedule`.

### Як налаштований будильник

Завдання `ss.ge_tbilisi` на [console.cron-job.org](https://console.cron-job.org/jobs) — клон завдання `ssge-watcher` (ss.ge Батумі), у якого змінено лише назву й адресу:

| Поле | Значення |
|---|---|
| URL | `https://api.github.com/repos/romario00724-glitch/ss.ge_tbilisi/actions/workflows/watch.yml/dispatches` |
| Розклад | Custom: хвилини `5,15,25,35,45,55`, кожної години (`5-55/10 * * * *`) |
| Request method | `POST` |
| Request body | `{"ref":"main"}` |
| Заголовки | ті самі три, що в інших завдань: `Accept`, `Authorization: Bearer github_pat_…`, `X-GitHub-Api-Version` |

Дві пастки cron-job.org: клон створюється з **вимкненим «Enable job»** (TEST RUN при цьому дає `204`, а за розкладом нічого не йде), а кілька хвилин у Custom-розкладі вибираються лише з затиснутим **⌘ Cmd**.

Ключ доступу — той самий fine-grained токен, що й у завдань `myhome-watcher`, `ssge-watcher` і `myhome_tbilisi`: до його доступу додано й цей репозиторій (`Actions: Read and write`). Тому й дата, коли він спливе, спільна: **28 вересня 2027**. Тоді замовкнуть усі боти, прийде лист від cron-job.org. Лікування — новий токен з доступом до всіх репозиторіїв, підставити в усі завдання на cron-job.org.

Коди відповіді будильника (кнопка **TEST RUN** унизу сторінки завдання): `204` — усе правильно; `401` — ключ сплив або скопійовано не повністю; `404` — ключу не дали доступ до цього репозиторію; `422` — не вставлено тіло `{"ref":"main"}`.

### Як перевірити, що бот живий

Відкрити [Actions репозиторію](https://github.com/romario00724-glitch/ss.ge_tbilisi/actions): якщо верхній запуск свіжий (не старший за ~15 хвилин) і зелений — усе гаразд. `нових оголошень немає` у логу — нормальна відповідь, а не поломка.

## Що означають позначки

У групі вони російською — ось як виглядають:

- **✅ У автора 1 объявление на ss.ge** / **⚠️ У автора 25 объявлений на ss.ge — агент или инвестор** — скільки оголошень у цього автора на всьому сайті (те саме число, що ss.ge показує в «Все объявления пользователя», працює з першого дня). З `AGENT_THRESHOLD` і більше — це агент під виглядом власника або інвестор із кількома квартирами (теж цікавий контакт).
- **⚠️ Этот автор или телефон уже встречался в N объявлениях — агент или инвестор** — власна база скрипта. З'являється, коли вона знає більше за сайт (наприклад, той самий телефон на кількох акаунтах).
- **⚠️ В описании упоминается агентство или комиссия.**
- **✍️ Пишет, что без посредников** — лише підказка, агенти теж так пишуть.
- Оголошення, автору яких ss.ge сам ставить значок **«Агент»**, бот не надсилає зовсім. Фільтр ss.ge «От собственника» відсіює лише компанії, а приватних агентів пропускає — без цього в групу йшли б і вони.
- Оголошення, де автор **прямо пише, що не співпрацює з рієлторами** («С агентствами не сотрудничаю», «Агентам не звонить», «Риелторов просьба не беспокоить», «Не сотрудничаю!»), бот не надсилає зовсім (лише в Тбілісі, з 12.10.2026). Якщо ж в описі є хоч якась співпраця («сотрудничаю 50%», «С риелторами — 50/50», «возможно сотрудничество») — надсилає, навіть коли поруч написано «не звоните». «Без посредников», «без комиссии», «агенты, не копируйте объявление» відмовою не вважаються. Перевірка — у файлі `no_realtors.py`.
- **🕒 07.10.2024 18:28, обновлено 30.09 14:20** — оголошення подане давно, а власник його щойно «підняв». На ss.ge таке буває часто; рік пишеться, коли він не поточний.

Телефон ss.ge віддає повністю.

## Налаштування (вгорі `watcher.py`)

- `AGENT_THRESHOLD = 3` — з якої кількості оголошень автора ставити ⚠️.
- `SKIP_SUSPECTED_AGENTS = False` — `True`, щоб таких узагалі не надсилати (рахується більше з двох чисел: на сайті чи в базі скрипта).
- `SKIP_SITE_AGENTS = True` — не надсилати оголошення, автору яких ss.ge ставить значок «Агент» (`False` — надсилати й такі).
- `SKIP_NO_REALTORS = True` — не надсилати оголошення, де автор пише, що не співпрацює з рієлторами (`False` — надсилати й такі). Лише в Тбілісі: цей рядок додає `sync_from_batumi.py`, тож змінювати його — у таблиці скрипта.
- `LANG = "ru"` — мова назв, описів і посилань (`ru` / `en` / `ka`).
- `MAX_ALERTS_PER_RUN = 25` — максимум повідомлень за одну перевірку.

Налаштування однакові з Батумі. Змінювати їх краще там, а сюди переносити скриптом (розділ нижче), — інакше наступне перенесення їх затре.

## Як перенести свіжий код із Батумі

Головний — бот Батумі (`ssge-watcher`): виправлення робляться там, а сюди переносяться готовими.

```
git -C ../ssge-watcher pull
python3 sync_from_batumi.py ../ssge-watcher/watcher.py
diff ../ssge-watcher/watcher.py watcher.py
```

Скрипт перезапише `watcher.py`, наклавши таблицю `REPLACEMENTS`: місто, російські тексти для групи й підключення фільтра «не сотрудничаю» з `no_realtors.py`. `diff` має показати лише рядки з таблиці. Якщо скрипт зупинився («очікував 1×, знайшов 0×…»), у Батумі змінився текст — поправте рядок у таблиці й запустіть знову. Нові тексти, які Батумі почне слати в групу, скрипт сам не помітить: після перенесення гляньте в `diff` на нові українські рядки в `send_text` / `build_message` і додайте їх у таблицю з перекладом.

## Якщо щось не так

- **HTTP 403 / «сторінка перевірки від Cloudflare»** — ss.ge прийняв запит за бота. На 403, 429 і 5xx бот сам пробує ще раз через 5–10 с. У лозі видно, хто відмовив: «ключ до API з головної» (сторінка home.ss.ge) чи «API ss.ge» (пошук). Разова відмова — не страшно: оголошення прийдуть наступного запуску. Перевірте, що встановлено `curl_cffi`. Якщо на GitHub це повторюється годину поспіль, бот сам напише в Telegram.
- **«немає фільтра міста»** — у посиланні немає `cityIdList=`. Застосуйте фільтри на сайті ще раз і скопіюйте адресу.
- **У Actions помилка push (403)** — Settings → Actions → General → Workflow permissions → **Read and write**.
- **Почати з нуля** — `python watcher.py --reset` (або видаліть `state.json` на GitHub).
- Скрипт працює через внутрішній API сайту: бере гостьовий ключ з головної сторінки ss.ge (так само робить браузер), а пошук, ім'я, телефон, лічильник оголошень автора й значок «Агент» — з `api-gateway.ss.ge`. Сторінки окремих оголошень ss.ge серверам GitHub не віддає, тому бот їх не відкриває. Якщо ss.ge це змінить, скрипт доведеться підправити — у Батумі, а потім перенести сюди.
